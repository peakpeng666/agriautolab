# headland_turn 槽位：范围界定研究（Study-002 scoping）

> 产出类型：**范围界定研究（scoping study）**，不是实现规格。
> 目的是回答一个二选一的问题：`headland_turn` 该不该进 Study-002。
> 全部 `file:line` 引用都用 grep 锚点实测核对过。

## 结论

**建议把 `headland_turn` 砍出 Study-002 候选槽位，列为 Study-003 候选。**
Study-002 用两个槽位（`swath_angle` + `route_order`），研究主张相应收缩为
**不主张全阶段自动设计**。

判据分两类，**先说已核实的**：

1. **path 阶段目前不存在逐转弯决策点**，开这个槽位是架构改动而非加一个函数（§1）；
2. **建它要跨过的已核实障碍有九条**，其中两条触及产物/配置契约本身（§2.2、§2.6）。

**未实测、只作推测的**（不足以单独支撑排除决定）：

3. 解析最短词在多数几何下唯一，启发式自由度可能天然窄——**未做候选空间实测**；
4. path 阶段可能是五阶段里评估最贵的——**本仓库没有分阶段耗时测量**，
   `PipelineTiming.planning_s` 覆盖整个五阶段计划，确定性闸对**所有槽位**都重跑
   整条流水线。该量的实测被 §4 列为反弹条件之一，**在测出来之前不应当作证据使用**；
5. 两槽位已足以支撑「多槽位互补演化」的研究主张——这是研究设计取舍，不是实测结论。

也就是说：**本文的结论建立在判据 1 与 2 上**。3–5 是支持性推测，若将来实测推翻其中
任何一条，结论仍然成立；反过来，若 1 与 2 被证伪（例如契约级障碍有了不外溢的解法），
结论就应当重新评估。

若保留的反弹条件见 §4。

## 1. 现状：为什么现在没有这个槽位

`pipeline/run.py` 的 `_PATHS` 注册表只暴露两个 wire ID：`dubins_transit` 与
`reeds_shepp_transit`。两者都把**整条路线一次性**委托给运动学求解——前者转交
`coverage.stages.path.DubinsPath.run(route, robot)`（Dubins 六字闭式解），后者由
`kinematics/reeds_shepp.py` 的 **8** 组 `BASE_FORMULAS` 经对称变换展开为 **48** 个 RS 词，
再正演采样。其 `_selection_candidates` 的候选集实际是 **RS 48 词 ∪ Dubins 前向 6 词**
（逐词闭合后去重）。**两者都没有 per-turn 决策点外露给候选**。

因此"让候选逐个地头转弯选策略"需要先让 path 阶段暴露选择点。这是架构改动，
不是新增一个启发式函数。

## 2. 若要建：已核实的障碍清单

以下每一条都经实测确认。它们既是 Study-003 的起手清单，也是本文建议
**现在不做**的量化理由。

### 2.1 转移段没有现成字段，必须自派生

`RouteArtifact` 契约只有两个成员：

```python
class RouteArtifact(BaseModel):
    traversals: tuple[SwathTraversal, ...]
    swaths: tuple[Swath, ...]
```

n 个 traversal 要按相邻两两配对派生出 n−1 个转移段：第 i 段起点 = 第 i 个
traversal 按其 `direction` 的出口端点，终点 = 第 i+1 个的入口端点。
**不应**扩展 `RouteArtifact` 塞 `transfer_segments`——它是刻意精简的产物契约，
派生量属于消费方。实现时应复用 PR #28 `route_order` 的 `entry_of` / `exit_of`。

### 2.2 `params` 装不下离散转弯类型

`pipeline/config.py` 的契约是 `params: Mapping[str, float]`，`StageMemo.key`
的形参标注同样是 `Mapping[str, float]`。把 `"curve_only"` 这类字符串直接塞进
`params` 会违反用于哈希与派发的配置 API。要么把枚举编码成**稳定数值**，
要么显式加宽并审计这个共享类型——后者会波及 `config_id` 的哈希输入，
需要单独论证 13 个冻结配置不受影响。

### 2.3 只注册 `_PATHS` 不够，必须补参数管线

`run_pipeline` 的 path 派发只给非 Reeds-Shepp planner 传采样步长，且只在 wire ID
**恰为** `reeds_shepp_transit` 时传 `allowed_region`。仅把新 ID 塞进 `_PATHS`，
新 planner 既拿不到候选的选择也拿不到 allowed_region，**不同候选会产出完全相同的
路径**。需要照抄 route 阶段 `ranked_swath_order` 的显式分支写法，并把 planner 的
`run` 签名加上接收选择的关键字参数。

### 2.4 记忆化键必须纳入候选的选择

中间产物按 `(阶段, 输入哈希, 算法, 参数)` 内容哈希记忆化。若键里没有转弯选择，
两个只在转弯上不同的候选会命中同一条缓存，第二个拿到第一个的路径——
**评估结果与候选无关，实验就是假的**。

### 2.5 独立复算必须复算"被选中的词"，而现有 API 只给最短词

`kinematics/dubins.py` 的公开 API 是
`dubins_words`（全部家族）/ `dubins_word`（跨家族取最短）/
`dubins_length`（跨家族取最短长度）/ `dubins_endpoint`。
后两者**忽略候选的选择**。候选故意选非最短家族时，拿它们复算会误拒合法候选，
或报出与所选转弯无关的代价。正确做法是从 `dubins_words` 里按选择挑出那一个词
再独立求值。

### 2.6 产物只存采样折线，无法与解析长度做 1e-6 级比对

`PathArtifact` 只有 `segments: tuple[PathSegment, ...]`，每段是
`line: LineStringSpec`（采样折线）加一个 `signed_curvature_m_inv` 标注。
弧被弦近似，步长来自 `PipelineConfig.params["path_sample_step_m"]`
（legacy 键 `dubins_sample_step_m`），缺省 0.25 m——**注意不是**
`BenchmarkProtocol.resample_step_m`：后者只是声明，path planner 并不读它，
照它去调不会改变这里讨论的偏差。**弦长与解析弧长的差远大于 1e-6**。
因此"解析长度 vs 产物长度，差异 > 1e-6 即抛"这类校验会把正确的曲线路径全部拒掉。
独立验证要么携带精确的原语长度，要么改成"独立复现同样的采样过程再比"，
并为此单独定义数值契约。**这一条实质抬高了独立 evaluator 的成本**。

### 2.7 `TransferBreakdown` 需要 cell 归属，而 `RouteArtifact` 不带

`metrics/path.py` 的 `transit_breakdown(path, *, cell_of_work_index=None)` 靠这个
映射区分 `turn_total_m` 与 `inter_cell_m`。`RouteArtifact` 刻意不携带 cell 归属，
所以只给 `path + route` 的 evaluator 在多 cell 路线上会把所有作业段间连接一律
当成转弯，**两个类别同时失真**，而 `other_m` 哨兵查不出来（残余仍为 0）。
evaluator 必须显式接收 `cell_of_work_index` 或能派生它的 `CellsArtifact`。

### 2.8 不变性闸不能按"选择序列逐位相等"实现

这一条在 PR #28 的 `route_order` 槽位上已实测确认，两个独立成因：

**(a) PCA 半平面翻转破坏索引对应。** `principal_axis` 的特征向量要过
`_sweep.canonical_direction`，后者强制 `ux > 0`。刚体旋转把特征向量带进左半平面时，
主轴与法向**一起翻转**，`swaths_along_direction` 反向枚举同一批物理条带——
索引 k 对应的是另一个段，有符号投影整体反号。90×50 田实测：旋转 1.5857 rad 后
逆变换回原坐标，条带中心 y 从 `12.85 / 22.55 / 32.25 / 37.15` 变成
`12.85 / 17.75 / 27.45 / 37.15`，**残余余量换到了另一端**，两组不是同一批几何对象。

**(b) 评分并列在刚体变换下任意翻转。** 并列由稳定枚举序决胜，而刚体变换引入
~1e-16 舍入；一旦某步翻转，后续序列整体发散。规则间距在 CPP 中极常见
（同一参考田第 1 步到两条条带的距离精确同为 9.7 m），不是边角情况。

**可行的判定量**：逐步逐选项比较**评分**而非比较选择序列，并把刚体变换施加在
**转移段几何**上而非地块上。闸门要拒的是"候选使用非不变特征"，评分比较直接命中
该性质，且对索引重排与并列都免疫。参考实现见 PR #28 的
`RouteOrderSlot.invariance_check`。

**参考田必须非对称。** 矩形上「余量换端 + 反向枚举 + 法向翻转」构成镜像对称，
不变键恰好抵消，错误实现照样能过——`route_order` 实测矩形漂移仅 1.4e-14，
梯形 3.10、L 形 27.3（24 次变换里 10 次连条带集合都不同）、楔形 24.7，容差 1e-9。

### 2.9 候选特征必须减去协变原点

段中点在法向上的投影 `p·n` 在平移下变为 `p·n + t·n`，整体加同一常数。纯排序看
不出（同序），但与距离量混合加权的候选次序会变，候选于是**因为平移而非自身缺陷**
被闸门拒。必须先减去随刚体变换协变的原点（地块质心或转移段集合质心）。
另：质心本身不能用外环顶点算术平均——闭合点重复计数，且插入共线冗余顶点会改变
结果（60×40 矩形得 (24,16) 而非 (30,20)）。两条都在 PR #28 修复并有回归测试。

## 3. 双向论证

### 3.1 支持进 Study-002

- **几何空间真实存在**：`reeds_shepp_transit` 的选词候选集是 RS 48 词 ∪ Dubins 前向 6 词，
  确实提供多个解析解家族；带障碍或可作业区收窄时不同家族可达性不同，
  选哪个家族是真实决策点。
- **互补性可能**：`swath_angle` 选长程方向、`route_order` 选访问序，
  `headland_turn` 决定端到端过渡，三槽位覆盖"长程几何 + 离散序贯 + 短程过渡"。
- **可证伪**：阴性结果（"演化在转弯选择上无法超越解析最短词"）本身有信息量。

### 3.2 反对进 Study-002

- **九条已核实障碍**（§2），其中 2.2 与 2.6 触及产物/配置契约本身，
  改动会外溢到冻结配置的哈希输入与既有 evaluator 的数值契约。
- **解析最短词主导（推测，未实测）**：闭式解在多数几何下给出唯一最短词，
  候选「选别的家族」可能只在边界几何上有自由度。**本仓库没有做过候选空间的
  覆盖度测量**，此条不足以单独支撑排除决定。
- **评估成本（推测，未实测）**：`PipelineTiming.planning_s` 覆盖**整个五阶段**
  计划，仓库里**没有分阶段耗时测量**；确定性闸对所有槽位都重跑整条流水线，
  因此也不能据它推断 path 阶段更贵。转移段数随条带数线性增长是结构事实，
  但每段成本未测。该量的实测已列入 §4 反弹条件，**在测出来之前不作为证据**。
- **协议纠缠**：与 `ReverseCostSpec` 耦合，而 Study-002 尚未定该参数。

  > 勘误：初稿把 `allowed_region` 也说成未定协议参数。实测 `run_pipeline`
  > **无条件**由 `FieldGeometry.from_problem(problem, vehicle).raw_free` 派生它，
  > 它由实现固定、不可经协议配置。因此本条只剩 `ReverseCostSpec` 一个真实耦合，
  > 论据进一步减弱。
  >
  > 二次勘误：上一版接着写「若将来要让转弯选择受可作业区影响，需先定义可配置的
  > allowed-region 契约」——**这也不对，是修过头了**。实测 `run_pipeline` 已经把
  > 派生出的 `raw_free` 传给 `ReedsSheppPathPlanner.run`，后者转交
  > `_contained_word` 用于挑选被包含的词族。未来的转弯选择器**直接复用这块固定
  > 且随几何协变的区域即可**，可配置性不是前提。真正需要补的只有 §2.3 的
  > 派发管线（把它传给新 wire ID），不是一项新的契约级改动。

  > 勘误：初稿曾写「`reverse_cost=0` 时所有解析解代价相等、极大时只能选直行」。
  > 两条都不成立——`reverse_length_multiplier` 的约束是 `ge=1.0`，取 0 在本仓库
  > 构造不出来；即便取 `(multiplier=1, penalty=0)`，不同家族几何长度本就不同，
  > 代价并不相等；罚则极大时解趋近**纯前向 Dubins 词**而非直行连接。
  > 用有效取值重述后本条**减弱**：真实耦合是两个参数共同决定含倒车家族相对
  > 纯前向家族的代价，从而改变候选可选面。结论不再主要依赖本条。

- **与两槽位重叠**：`swath_angle` 已定长程方向、`route_order` 已定哪些段相邻，
  转弯选择的很多自由度被前两者隐式锁定。

## 4. 对 Study-002 的影响与反弹条件

**影响（建议，尚未生效）**：Study-002 的槽位集合应定为
`{swath_angle, route_order}`，研究主张写成「多槽位互补演化」而**不是**
「全阶段自动算法设计」；预注册的 `non_goals` 应显式列入 `headland_turn` 并引用本文。

> **本文尚未改变仓库的既定路线图。** `docs/TURNING_POINT.md` 第三节仍把 Study-002
> 定义为**三槽位**研究，而它是本仓库当前生效的计划。两处并存会让照路线图执行的人
> 预注册出与本文直接矛盾的范围。
>
> 处置：本文的槽位结论**暂列为建议**，须由所有者在采纳时**同步更新
> `TURNING_POINT.md`**，之后本节措辞才改为终局。本 PR 不动
> `TURNING_POINT.md`——它属于冻结章程，改它需要单独的、可被审阅的决定，
> 不应搭在一份 docs-only 的范围界定研究里顺手带过。

**反弹条件**（满足则重新评估）：

1. PR #28 合并后实测单次评估成本，确认 path 阶段增量在预算内
   （参考量级：Study-001 corpus 为 61,100 次运行）；
2. §2.2 与 §2.6 两条契约级障碍有了不外溢的解法；
3. Study-002 的协议参数 `ReverseCostSpec` 已冻结。
   （`allowed_region` 不在此列：它由实现无条件派生，不是可冻结的协议参数。）

初稿是一份精确到函数签名的实现提案，评审据此按 spec 审出多轮技术错误。

不应包含未经验证的 API 级设计。

本次重写把实现提案降级为 §2 的**已核实障碍清单**——每一条原本是"提案中的缺陷"，
现在是"支持不做该槽位的证据"，且全部有 `file:line` 或实测数据支撑。
同时修掉一处自相矛盾：§3.1 已改为评分口径，而旧 §3.2 表格仍写着
`tuple(rotated) == tuple(base)`。

已删除的内容：`kinematics.dubins.length_optimal`、`RouteArtifact.transfer_segments`
（两者都不存在）、以及全部未经验证的函数签名与改动面清单。
结论自始至终未变。

**后续两轮又暴露了同一个失败模式**：断言了没有实测的数字与字段名。已逐条修正
（Reeds-Shepp 是 8 组 `BASE_FORMULAS` 展开成 48 词而非「九组 / 46 词」；采样步长来自
`params["path_sample_step_m"]` 而非 `BenchmarkProtocol.resample_step_m`；

分阶段耗时测量支撑，已降级为标注「未实测」的推测）。

作为根因处置，本文**全部 21 条事实断言**（wire ID 集合、契约字段、函数签名、
类型标注、数值约束、计数、上下游取值来源）已用一次性脚本逐条与代码核对，
现全部通过。此后再修改本文的任何事实陈述，都应重跑同类核对而不是凭印象下笔。
